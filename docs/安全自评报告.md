# 老年人「语音数字银行管家」安全自评报告

## 一、系统边界与测试环境

本项目是面向老年人的语音优先银行智能体演示系统，运行在**模拟银行沙箱**中。系统不连接真实银行核心系统、不执行真实资金交易，账户余额、交易流水、理财持仓、卡片和授权票据均为演示数据。

默认测试环境为：

- 意图理解：确定性规则解析器（未配置大模型时自动降级）
- 语音识别：浏览器原生识别
- 语音合成：浏览器语音合成
- 初始活期余额：`¥28,650.00`
- 默认免密额度：`¥200`
- 子女授权门槛：`¥2,000`

## 二、权限分级实现说明

系统将涉及资金和账户安全的操作划分为四级：

| 等级 | 主要条件 | 系统动作 |
|---|---|---|
| L0 | 白名单收款人且金额不超过免密额度 | 语音复述后执行 |
| L1 | 中等金额或需要增强确认的操作 | 语音复述 + 大字二次确认 |
| L2 | 大额、首次收款人、异地、深夜、新设备或行为异常 | 生成一次性授权票据，由子女审批 |
| L3 | 高危收款人、诈骗话术、注入、声纹不匹配、第二说话人、余额/限额越界或紧急止付 | 直接阻断并留痕通知 |

权限裁定由确定性规则引擎完成，模型只能提供意图槽位和辅助风险信号，不能直接调用资金接口，也不能降低已确定的风险等级。语义风险信号最高只能将操作提升至 L2。

## 三、关键安全控制

### 1. 授权票据

- 票据绑定老人账户、金额和收款人。
- 子女审批只能维持或下调金额，不可更换收款人或放宽额度。
- 票据一次有效，使用后不可重放。
- 默认 5 分钟超时自动作废。
- 执行前再次校验票据、金额、收款人和当前余额。

### 2. 幻觉防护

模型返回的金额和收款人必须能够在用户原话中得到验证；不一致时中止或回落到规则解析器。复述文本还要与最终执行参数再次比对，避免模型生成不存在的转账参数。

### 3. 注入防御

备注、商户名称和账单描述等外部文本被当作不可信数据处理，不参与执行指令解析。诈骗话术、指令注入、声纹不匹配和第二说话人等高危信号由规则引擎处理，命中后阻断或升权。

### 4. 审计与完整性

审计记录按“意图 → 计划 → 风险判定 → 确认 → 执行”记录，并通过前序哈希和 SHA-256 当前哈希形成链式校验。`GET /audit/verify` 可检测记录篡改和断链；配置 `AUDIT_DB_PATH` 后可持久化到 SQLite。

### 5. 幂等与账户隔离

执行过程使用锁和会话状态防止重复扣款；重复执行同一会话返回原结果，不新增流水。账户、流水、限额、行为证据、票据和通知均按老人账户隔离，未知账户和子女账户不能发起老人计划。

## 五、已知风险与生产边界

1. 当前锁机制为单进程保护；多实例生产部署必须使用数据库事务、幂等键和行级锁。
2. 当前审计持久化使用 SQLite；生产环境应迁移到具备访问控制、备份和不可变归档能力的审计存储。
3. 浏览器原生语音识别和语音合成受浏览器、麦克风权限和设备环境影响，关键操作仍保留文字输入和确认流程。
4. 大模型语义反诈仅作为辅助信号，不能替代确定性风控、人工审核、复述确认和子女授权。
5. 声纹、第二说话人和设备信号在当前项目中以接口和模拟字段呈现，接入真实银行时需要经过独立的模型验证、隐私评估和合规审查。
6. 项目中的账户、联系人和交易数据仅用于演示；上线前必须完成真实数据脱敏、密钥管理、访问控制、日志留存和灾备设计。

## 六、自评结论

在模拟银行沙箱和当前测试口径下，系统已完成权限分级、注入防御、幻觉防护、授权票据、审计完整性、幂等保护和多账户隔离的实现与验证。系统适合比赛演示、技术评审和试点验证；不应在完成真实银行核心接入、生产级并发控制、身份认证、密钥管理和合规审查前直接用于真实资金业务。
